上一个博客是 WordPress。跑了一年多，挂在一台 1G 内存的小机器上，PHP 和 MySQL 常驻吃掉了差不多 400M。其实没有什么复杂需求：写文章、看文章、留两个标签。于是决定搬回静态。

## 为什么是 Hexo

候选大概三个：Hugo、Hexo、Astro。

Hugo 单文件二进制，构建速度快得离谱，模板语法我始终没习惯；Astro 很舒服，但依赖树的体量对一个纯博客来说有点过度设计；Hexo 是我最早用过的，Node 生态，`hexo new` 一条命令就够了，出问题的时候 `node_modules` 里什么都看得见。

选 Hexo 不是因为它是"最好"的，而是因为我对它的心智模型最熟，遇到问题的时候不需要再学一套东西。

## 为什么不直接用现成主题

试过几个热门主题，问题基本集中在两点：

1. **加载了太多东西**。字体从 CDN 拉三份、图标库一整套、分析脚本两个、评论系统一个。首屏请求数轻松上到三十几个，全是我自己写给自己看的博客。
2. **视觉上太"模板"**。渐变、毛玻璃、大圆角、每个标题前面一个 emoji、卡片 hover 时往上飘 4px 加一圈阴影。不是说这些不好，只是它们和我想要的东西不一样。

于是决定自己写。给自己定了几条约束：

- 只有一个强调色，其余全靠灰阶层次
- 等宽字体贯穿全站，包括正文
- 不用圆角、不用阴影、不用渐变
- 动效只在必要的状态变化上出现
- 不请求任何外部资源（字体、图标、脚本一个都不要）
- 关掉 JavaScript 也要能正常阅读

## 结构

主题目录就是标准的 Hexo 主题布局，没有构建步骤，改完 `hexo s` 直接看效果：

```
themes/tty/
├── _config.yml          # 主题独立配置，不污染站点配置
├── layout/
│   ├── layout.ejs       # 外壳
│   ├── index.ejs        # 首页
│   ├── post.ejs         # 文章页
│   ├── page.ejs
│   ├── archive.ejs
│   ├── tag.ejs / tags.ejs
│   ├── category.ejs
│   ├── 404.ejs
│   └── _partial/
│       ├── post-row.ejs
│       ├── pager.ejs
│       └── comments.ejs
└── source/
    ├── css/style.css
    ├── css/hljs.css
    └── js/tty.js
```

CSS 全部用原生的自定义属性，主题配置里的颜色项在模板里注入到 `:root` 上，改颜色不用碰样式表。

## 代码高亮的配色

现成的配色方案大多在浅色背景上更好看。自己配一套，原则是和终端 ANSI 色板对齐，只取几个色：

| 用途 | 色值 | 大致对应 |
| --- | --- | --- |
| 关键字 | `#7ec8e3` | 亮青 |
| 字符串 | `#9ecb7f` | 亮绿 |
| 数字 | `#d9a441` | 黄 |
| 函数名 | `#3ddc84` | 主色 |
| 注释 | `#545b57` | 暗灰 |

代码块外面包了一层 26px 高的标题栏，上面只有三个小圆点，模仿终端窗口。复制按钮默认透明，鼠标移上去才出现。

## 关于"去 AI 感"这件事

写完第一版之后回头看，有几处明显是照着模板的惯性写的，都删掉了：

- 首屏那种"Hi, I'm X 👋"配一张头像的大字号宣言
- 每篇文末自动生成的"总结"和"分享到 ×××"
- 悬浮在右下角、跳动着的"回到顶部"按钮
- 页脚一长串图标

现在首页第一行是 `~$ whoami`，下面是文章列表，按时间倒序，带序号和阅读时长。就这样。

## 剩下的
